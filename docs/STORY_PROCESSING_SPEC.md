# Story Processing Specification

## Objective

Convert a complete text, Markdown, or text-based PDF story into traceable structured data before season and episode generation.

## Pipeline

```text
Validate
→ Parse
→ Normalize
→ Preserve pages/sections
→ Chunk
→ Embed
→ Retrieve
→ Complexity analysis
→ LLM extraction
→ Entity resolution
→ Timeline/continuity
→ Master script
→ Duration estimate
→ Season/episode planning
```

## Invariants

- Original source text is never discarded.
- Every extracted fact must have source references where possible.
- Narrative order and chronological order are stored separately.
- Scanned PDFs are rejected.
- Embeddings are never sent directly to the LLM.
- Episodes are generated by the system, not manually created.

## Chunking defaults

```text
Target: 900 words
Overlap: 100 words
```

Each chunk stores narrative position, chapter title, page range, token estimate, and source metadata.

## Complexity profiles

```text
standard | complex | temporal | multi_world
```

The profile controls retrieval depth and later LLM analysis strategy.

## Completion criteria

A source is ready for LLM analysis only when parsing, chunking, and all embedding jobs have succeeded.
